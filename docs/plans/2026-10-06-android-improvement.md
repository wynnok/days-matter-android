# Android 专属精进与平台适配方案

日期：2026-10-06。状态：核心方向已确认，尚未实施。本文只维护 Android 的设备能力和平台适配；基础功能、日期、摘要、备份及外观规则统一引用[两端共通方案](2026-10-06-shared-improvement.md)。

可执行 spec 已发布为 [GitHub Issue #3](https://github.com/wynnok/days-matter-android/issues/3)，标记 `ready-for-agent`，依赖 [共通 spec #2](https://github.com/wynnok/days-matter-android/issues/2) 的业务规则。本文保留规划依据，后续实施和完成验收以对应 spec 为准。

## 1. 范围与依赖

本轮专属内容为本地提醒与权限、离线缓存、系统生命周期及后台刷新、事件定位、桌面小组件，以及“我的”和文件交互的平台适配。

资料保存反馈、分类管理、账号备份、站外提醒和三种外观仍属于共通能力；即使某项目前只需 Android 补齐，也在共通方案对应条目追踪，不重新定义业务规则。

| 编号 | Android 工作 | 共通依赖 | 优先级 |
| --- | --- | --- | --- |
| A01 | 离线缓存状态与重试、生命周期及后台更新接入 | C01 日期、C02 数据状态 | P0 |
| A02 | 本地提醒概览、通知权限、系统通知设置、测试通知和排查 | C01 日期；ADR-0001 设备提醒归属 | P0 |
| A03 | 小组件／本地通知到事件详情的路由及账号校验 | C02 登录与数据状态 | P0 |
| A04 | “我的”管理中心＋轻量摘要的平台布局和入口 | C04–C08 | P1 |
| A05 | 小组件发现、添加说明、实例管理和重新配置 | C01、C07 | P1 |
| A06 | Android 文件选择、实际写入及导入预览接入 | C03 账号备份 | P0 |
| W01 | 重要日子：固定关注一个主事件 | A01、A03、A05 | P1 |
| W02 | 近期日程：窗口、分类、有限列表和尺寸适配 | A01、A03、A05、C01 | P1 |

目前本地提醒已在事件编辑页，分类管理已在首页抽屉；桌面小组件尚未实现，`ui/Widgets.kt` 是应用内控件。事件天数仍取缓存结果，事件路由尚未处理。这些是本地代码事实，不是线上或真机验收结果。

## 2. “我的”与设备管理

### 2.1 平台信息结构

```text
我的
  个人资料：默认头像、昵称、邮箱、编辑
  轻量摘要：事件总数｜近期 7 天
  提醒与权限：本地提醒｜站外提醒
  数据与同步：同步状态与重试｜账号数据备份与导入
  分类与偏好：分类管理｜外观
  桌面小组件：添加说明｜已有实例与配置入口
  关于与帮助：版本｜使用帮助｜项目与第三方声明
  退出登录
```

首页负责日程浏览，“我的”负责管理。摘要保持一行，口径引用 C06；沿用现有配色、间距和卡片规范。分类入口复用已有管理逻辑，站外提醒引用 C05，资料反馈引用 C02／C04，不建立第二套业务逻辑。

Android 版本、第三方声明、本地通知、省电及小组件帮助放在当前端的关于／帮助中；通用说明引用 C08。预设头像和默认提醒参数是后续候选，不加入本轮基础范围。

### 2.2 A02：本地提醒与权限

本地提醒页回答：哪些事件配置了提醒、当前设备能否显示通知、遇到问题如何排查。提供已启用提醒的事件列表、下一次已知提醒时间、权限／系统应用通知开关状态、测试通知和系统设置入口。

发生日期未知或重复日期已过时标注需要同步。当前配置的本次提醒时间已过时说明时间已过；不能仅凭开关已启用声称仍有待发送通知，也不能据此判断之前是否实际送达。测试通知只验证当下展示链路，不保证未来定时送达；省电影响用简短帮助解释。

首轮保持逐事件设置，不增加覆盖所有事件的提醒开关或批量修改。本地提醒归设备，站外提醒归账号。通知权限关闭不阻止小组件显示。

### 2.3 A01／A06：缓存状态与文件适配

| Android 状态 | 展示与操作 |
| --- | --- |
| 同步中 | 保留原内容，防止重复触发 |
| 已同步 | 展示上次成功同步时间，可立即同步 |
| 离线但有缓存 | 标注缓存和上次成功同步时间，可阅读，联网后重试 |
| 同步失败但有缓存 | 保留缓存，提供重试与简短原因 |
| 首次没有缓存 | 尚无已同步数据；与确实无事件区分 |
| 检测到登录失效 | 要求登录，清理或遮蔽该账号的桌面内容 |

当前 `syncedAt` 仅是设备记录的请求完成时间，不代表服务端计算日期。失败不更新成功时间，离线修改或导入应说明需要联网并保留输入。Android 的日期展示遵循 C01 和 ADR-0002，不复制农历／重复周期算法。

A06 使用系统文件选择和保存。取消或文件未实际写入不能显示导出成功；最近成功保存记录仅在写入完成后更新。导入预览、追加确认、结果未知及后续刷新失败均引用 C03，不能把超时直接视为未写入并引导再次提交。

## 3. 桌面小组件：展示什么，怎样使用

### 3.1 两类用途

| 小组件 | 用户问题 | 核心数据 | 推荐尺寸 |
| --- | --- | --- | --- |
| 重要日子 | 我一直关注的这件事还有多久，或已经过去多久？ | 事件名称、天数／今天、发生日期；有空间时显示分类 | 2×2、4×1 |
| 近期日程 | 最近有哪些日子需要留意？ | 近期事件列表，每条名称、天数和日期；顶部显示窗口／分类 | 4×2、4×4 |

尺寸是桌面网格上的设计参考，实际按可用空间适配；不同桌面与字体大小下优先保证可读性。首轮不展示邮箱、账号资料、Webhook 地址、提醒内容或子事件明细，避免挤占事件信息。

### 3.2 W01：重要日子

用户主动选择一个主事件，实例持续关注该事件，不因首页排序或新增事件自动更换。

| 信息层级 | 展示内容 | 规则 |
| --- | --- | --- |
| 首要 | 剩余 N 天／今天／已过 N 天 | 数字醒目，方向词明确；日期待确认时用状态文案替代数字 |
| 次要 | 事件名称 | 小尺寸保留名称；长名称最多两行，按空间截断 |
| 辅助 | 本次发生日期 | 展示明确的公历日期；农历事件可在较大尺寸补农历标识 |
| 装饰 | 分类图标与颜色 | 提升识别，不让颜色承担唯一的状态表达 |
| 状态 | 缓存／待同步提示 | 离线或同步异常时提供上次同步时间 |

示例：

```text
重要日子
妈妈的生日
还有 12 天
本次日期：10 月 18 日
```

不重复的事件过去后，显示“已过 N 天”。重复事件的已知日期过去后，显示“待同步下一次日期”，保留事件名称和上次已知日期，不把它当作已结束的事件累计天数。

点击主体进入该事件详情。没有可用事件时显示“添加一个重要日子”，点击进入应用创建；取消配置不替换已有实例的原配置。删除所选事件后显示“事件已删除，请重新选择”，不自动换成别的事件。

### 3.3 W02：近期日程

默认采用共通 C01 的“近期 30 天”窗口，允许改为“近期 7 天”；可选全部分类或指定一个分类。窗口、主事件及待同步含义统一引用共通方案，首轮不增加复杂组合筛选。

默认展示最靠近今天的 3 条；较大尺寸或较小字体可增加到 5 条，超过可展示数量时提供“查看全部”入口。首版采用有限列表，暂不加入滚动、翻页或自动轮播。

列表只包含发生日期已确认、处于所选窗口的主事件，排除过去事件。按照发生日期由近到远排序，同一天内置顶事件优先，再按名称和稳定标识排序。远期置顶事件不会挤掉更近的事件；这个规则独立于首页现有“置顶优先＋天数绝对值”排序。

示例：

```text
近期 30 天 · 全部分类
今天       项目上线
还有 3 天  朋友生日       10/09
还有 12 天 妈妈的生日     10/18
查看全部
```

点击一条进入事件详情；标题／“查看全部”打开首页并应用选定分类，近期窗口只限制小组件展示范围。空间允许时提供新增事件和手动刷新入口，各按钮保持足够的点击区域。

窗口内没有已确认事件时显示“近期没有日程”；如果同时存在日期待确认的事件，应补充“另有 N 个事件待同步”，提供刷新入口。分类被删除后进入“分类不可用，请重新选择”，不悄悄切换到全部分类。

### 3.4 配置与外观

每个放置在桌面的实例独立配置，互不影响：重要日子保存所选事件，近期日程保存窗口与分类，两类均可选择浅色、深色、跟随系统。默认跟随系统；分类色仅作点缀，优先保证文字对比度。

添加时预览真实展示效果，并说明内容会在桌面可见。使用系统的小组件选择和配置入口；“我的”提供发现、添加说明和已有实例入口。支持系统重新配置的版本优先使用系统入口，低版本提供应用内对应实例的调整入口。支持多个实例关注不同事件或分类，选择事件不修改其置顶状态。

头像、照片背景、透明背景、多套字体及任意主题色暂列 P2；首轮不让样式选择增加使用门槛。

## 4. Android 刷新与事件定位

### 4.1 刷新策略

账号数据获取与已有日期的重新展示分开：无网络时仍可推进已确认日期的显示天数，联网后再尝试同步。实例复用账号快照，不为每个实例单独请求一套接口。

| 触发条件 | 预期行为 |
| --- | --- |
| 应用成功同步、修改或删除事件 | 更新相关实例，各页面使用同一份数据 |
| 首次添加／配置完成／尺寸变化 | 用当前数据立即生成适配内容 |
| 业务日期变化后的首次刷新 | 遵循 C01 重算天数；重复日期过期时尝试同步 |
| 回到前台或恢复网络 | 数据需要更新时尝试同步并更新展示 |
| 用户手动刷新 | 成功后更新；失败保留缓存和状态提示 |
| 设备重启、时间变化 | 恢复实例读取，重新计算日期并按条件同步 |
| 周期后台任务 | 提供恢复与刷新机会；建议小时级起点，按实测耗电和及时性调整 |

系统允许刷新时更新，不承诺零点精确切换，不使用分钟级轮询或前台常驻服务。平台依据见 [Glance 更新与状态管理](https://developer.android.com/develop/ui/compose/glance/glance-app-widget)。这套调度策略只适用于 Android，不作为网页后台运行要求。

### 4.2 A03：账号与事件路由

实例配置归设备并关联所属账号及后端，不能只按事件 ID 识别。退出、检测到登录失效或切换账号时，主动把桌面旧内容替换为登录／重新配置提示；清除应用缓存不代表桌面旧内容自动消失。离线时不能保证立即得知服务端撤销会话。

小组件和本地通知共用事件定位：保留所属账号与目标事件，需要登录时只有重新登录所属账号才恢复目标，其他账号不恢复旧目标。事件暂未缓存与确认已删除分别处理，必要时先同步，再回退首页并解释原因。

| 小组件场景 | 展示与操作 |
| --- | --- |
| 未登录 | 提示登录，点击打开应用 |
| 登录后没有缓存 | 尚未同步，提供打开应用／刷新入口 |
| 离线但有缓存 | 展示已知内容，标注缓存与上次同步时间 |
| 同步失败 | 保留可用内容，说明尚未获取最新数据 |
| 重复日期已过 | 按 C01 等待下一次日期，不推导周期 |
| 事件或分类已删除 | 提示重新选择，不自动替换绑定对象 |
| 所属账号不是当前账号 | 隐去内容，提示登录所属账号或重新配置 |
| 点击时事件暂不可用 | 尝试同步；确认不存在后回到首页 |
| 通知权限关闭 | 小组件正常显示；本地提醒问题在应用内解释 |

## 5. Android 后续路线与交付顺序

| 候选方向 | 范围与条件 |
| --- | --- |
| S01-A：本地提醒可靠性 | 日期与参数边界、重启恢复、通知点击定位及系统限制回归 |
| S04-A：设备配置迁移 | 本地提醒、外观、桌面配置的迁移；独立于 C03 账号备份，明确映射与平台限制后再设计 |
| S06-A：小组件个性化 | 更多样式、照片背景、字体等；两类基础小组件稳定后再评估 |

其他整体完善方向统一维护在共通方案，不另建一份搜索、归档或账号保障路线。

| 阶段 | Android 交付 | 完成标准 |
| --- | --- | --- |
| A：可信基础 | 接入 C01–C03；A01 缓存、A02 本地提醒、A03 路由、A06 文件流程 | 跨日与离线状态可信，账号和路由不串用，提醒／文件结果明确 |
| B：我的与重要日子 | A04／A05，补齐相关共通能力，W01 | 管理入口完整，单事件可添加、查看、更新、重配 |
| C：近期日程 | W02 | 窗口、分类、排序、空状态与多实例独立性正确 |
| D：持续完善 | 按实际痛点选择共通或专属候选 | 每批有独立目标及验收 |

日期展示是摘要和两类小组件的共同前置；路由是小组件和本地通知点击的前置。管理页分组与帮助可以并行推进，先验证 W01，再复用稳定基础完成 W02。工期在接口、设备限制和任务拆分确认后估算，不要求迁移数据库或更换架构。

## 6. Android 验收

共通功能先满足对应 CV 验收，以下只补充平台场景：

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AV01 | 首页、详情、“我的”和小组件显示同一事件 | 按 C01 得到一致日期与天数 |
| AV02 | 离线连续多天、设备处于其他时区 | 下次刷新按东八区推进已确认日期；缓存新鲜度明确 |
| AV03 | 离线时重复日期已过 | 显示待同步，不猜测下一周期或错误累计 |
| AV04 | 断网恢复、前台返回或手动重试 | 失败不清空缓存；成功后更新所有实例及成功时间 |
| AV05 | 近期边界、过去事件、同日事件及远期置顶 | 继承 C01 窗口，近日期优先，不被远期置顶挤掉 |
| AV06 | 多个实例选择不同事件／分类 | 配置、更新和删除互不串用 |
| AV07 | 事件或分类被修改／删除 | 更新或提示重新选择，不隐式更换绑定 |
| AV08 | 退出、登录失效、切换账号及相同事件 ID | 清理或遮蔽旧桌面内容，路由不进入其他账号事件 |
| AV09 | 小组件／通知点击，未登录或目标暂不可用 | 正确定位、同步或明确回退，所属账号登录后恢复目标 |
| AV10 | 长名称、大字体、浅深色、不同尺寸和桌面 | 核心信息可读，点击区域可用，无裁切或失效内容 |
| AV11 | 重启、后台受限或长期不打开 | 恢复读取，延迟刷新不被表述为精确实时更新 |
| AV12 | 通知权限或应用通知关闭 | 提醒概览指出原因，小组件不受阻；测试不声称未来送达 |
| AV13 | 文件选择取消、写入失败或成功 | 仅实际保存成功后记录和提示；导入结果满足 C03 |
| AV14 | 添加配置取消、重配和系统主题变化 | 不覆盖旧配置，各实例外观独立、跟随系统有效 |

布局、预览、空状态、点击区域和操作后更新对照 [Android 小组件质量指南](https://developer.android.com/docs/quality-guidelines/widget-quality) 验证。功能实施后需相应测试及真机检查；本文未执行这些功能验收。
